# Environment Variables

Only `backend` and `frontend` read environment variables. `courier-app`, `сhef-panel` and `ower-panel` have no `.env` file — their API clients hard-code `http://localhost:3000`.

## Backend — `backend/.env`

Copy `backend/.env.example` to `backend/.env`.

```
# Stripe
STRIPE_SECRET_KEY=
STRIPE_PUBLISHABLE_KEY=
STRIPE_WEBHOOK_SECRET=

# Neon PostgreSQL
POSTGRES_URL=

# JWT
JWT_SECRET=
JWT_REFRESH_SECRET=
JWT_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=7d

# File upload
MAX_FILE_SIZE=5242880
UPLOAD_PATH=./uploads

# Image services (for seeds)
UNSPLASH_API_KEY=
PEXELS_API_KEY=
PIXABAY_API_KEY=

# Server
PORT=3000
NODE_ENV=development
```

Key points:

- `POSTGRES_URL` — the Neon connection string; also read by `backend/drizzle.config.ts` for `db:push` / `db:generate`.
- `JWT_SECRET` and `JWT_REFRESH_SECRET` are captured at module-load time in `backend/src/utils/auth.ts`, so `.env` must be loaded before startup and import order matters.
- `STRIPE_PUBLISHABLE_KEY` is the backend copy; the frontend uses its own `PUBLIC_STRIPE_PUBLISHABLE_KEY`.
- `UNSPLASH_API_KEY` / `PEXELS_API_KEY` / `PIXABAY_API_KEY` are used only by the seed script for demo images.

## Frontend — `frontend/.env`

Copy `frontend/.env.example` to `frontend/.env`.

```
PUBLIC_API_URL=http://localhost:3000
PUBLIC_WS_URL=ws://localhost:3000/ws

# Stripe (copy from root .env.base)
PUBLIC_STRIPE_PUBLISHABLE_KEY=
```

Variables are read through `$env/static/public` in `src/lib/api.ts`, so only names prefixed with `PUBLIC_` are exposed to the browser.

## Apps without `.env`

| Application | API URL |
|-------------|---------|
| `courier-app` | `http://localhost:3000` (`src/api/client.js`) |
| `сhef-panel` | `http://localhost:3000` (`src/api/axios.ts`) |
| `ower-panel` | `http://localhost:3000` |

These are hard-coded; the chef Vite `/api` proxy is configured but not used by its API client.
