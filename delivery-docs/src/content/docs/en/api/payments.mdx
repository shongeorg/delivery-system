# Payments

Card payments run through Stripe. `POST /payments/create-intent` and `POST /payments/confirm` require `Authorization: Bearer <accessToken>`; the webhook is authenticated by the Stripe signature.

## Endpoints

| Method | Path | Access | Description |
|--------|------|--------|-------------|
| POST | `/payments/create-intent` | order owner | Creates a PaymentIntent, returns `clientSecret` |
| POST | `/payments/confirm` | order owner | Verifies the PaymentIntent and sets `paid` |
| POST | `/payments/webhook` | Stripe signature | Handles `payment_intent.succeeded` / `.failed` |

## Create Payment Intent

`POST /payments/create-intent`

```json
{ "orderId": "…" }
```

Only the order owner may pay; an order that is already `paid` returns `400 Order already paid`. The amount is the order total in cents, currency `usd`.

Response `200`:

```json
{ "clientSecret": "…", "paymentIntentId": "…" }
```

Errors: `404 Order not found`, `403 Forbidden`, `400 Order already paid`.

## Confirm Payment

`POST /payments/confirm`

```json
{ "orderId": "…", "paymentIntentId": "…" }
```

The server retrieves the PaymentIntent, checks that its `metadata.orderId` matches the order and that its status is `succeeded`, then sets the order to `paymentStatus: paid` and `status: paid`.

Response `200`: `{ "success": true, "order": { … } }`.

Errors: `404 Order not found`, `403 Forbidden`, `400 Payment does not match order`, `400 Payment not completed`.

## Webhook

`POST /payments/webhook` — called by Stripe and verified through the `stripe-signature` header and `STRIPE_WEBHOOK_SECRET`.

- `payment_intent.succeeded` — sets `paymentStatus: paid` and `status: paid`, then notifies the customer.
- `payment_intent.payment_failed` — sets `paymentStatus: failed`.

Returns `{ "received": true }`. An invalid signature returns `400`.
