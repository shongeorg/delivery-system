# Права ролей

Авторизація побудована на заголовку: кожен захищений запит несе `Authorization: Bearer <accessToken>`. `authMiddleware` кладе `userId` і `userRole` у контекст запиту, а `allowRoles([...])` обмежує ендпоінт набором ролей (`backend/src/middleware/auth.ts`).

## Ролі

| Роль | Призначення |
|------|-------------|
| `customer` | Вітрина, кошик, власні замовлення, трекінг, чат замовлення |
| `courier` | Черга доставок, прийняття, маршрут, локація, чат, доставлено |
| `chef` | Черга кухні, статуси `created → cooking → ready`, склад, рецепти |
| `owner` | Усе, включно з персоналом, зарплатами, фінансами, налаштуваннями, аудитом |
| `admin` | Те саме, що owner, крім зміни власника; входить і в owner-панель, і в кухню |

## Хто що бачить і робить

| Роль | Бачить | Може змінювати |
|------|--------|----------------|
| `customer` | Свої замовлення, трекінг, чат | Створити замовлення, скасувати до `paid`, писати в чат |
| `chef` | Усі замовлення (`GET /orders`), кухню | `created → cooking → ready`, `cancelled` |
| `courier` | Усі доставки (список `ready` + `on_the_way`) | Прийняти (`on_the_way`), завершити (`delivered`), локація, чат |
| `owner` / `admin` | Усе | Будь-який дозволений перехід, фінанси, персонал |

Важливо: `GET /orders` віддає **всі** замовлення — воно не фільтрується за кур'єром. Кур'єрський застосунок фільтрує на клієнті (`deliveryType === 'delivery'`, статус `ready` / `on_the_way` / `delivered`), тому два кур'єри бачать той самий список «доступних», а бекенд вирішує, хто перший натиснув Accept.

## Хто ставить кожен статус

| Статус | Хто ставить |
|--------|-------------|
| `created` | Система (`POST /orders`) |
| `paid` | `POST /payments/confirm` або вебхук Stripe |
| `cooking` | `chef`, `admin`, `owner` |
| `ready` | `chef`, `admin`, `owner` |
| `on_the_way` | Тільки `courier` |
| `delivered` | Призначений `courier` або staff |
| `cancelled` | Клієнт (до `paid`), `owner`/`admin` (до `on_the_way`) |

## Правила, які забезпечує бекенд

- Переходи статусів валідуються за `allowedTransitions` у `backend/src/routes/orders.ts`. Будь-який інший перехід повертає `409`.
- Кур'єр може ставити лише `on_the_way` і `delivered`, лише з `ready` і лише якщо замовлення не призначене іншому:
  - `409 Order already accepted by another courier` — `courierId` уже встановлений.
  - `403 Order is assigned to another courier` — замовлення належить іншому.
- Скасування має окремий ендпоінт `POST /orders/:id/cancel`, а не матрицю переходів: клієнт може скасувати лише власне замовлення у статусі `created` або `paid`. Після `cooking` цей ендпоінт повертає `400`.

## Коди помилок

| Код | Значення |
|-----|----------|
| `401` | Відсутній або невалідний токен |
| `403` | Роль не дозволена, або замовлення призначене іншому кур'єру |
| `409` | Перехід заборонений, або замовлення вже прийнято |
