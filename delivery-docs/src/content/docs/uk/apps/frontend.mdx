# Frontend (SvelteKit)

Вітрина для клієнта: перегляд каталогу, формування кошика, оформлення замовлень і відстеження доставки. Побудована на **SvelteKit 5** (режим runes примусово увімкнено для всіх файлів застосунку) і **Tailwind CSS 4**. Працює на порту `3031` і це єдиний клієнт, який бере адресу бекенду зі змінної середовища.

## Стек, порт, роль

| Стек | Порт | Роль |
|------|------|------|
| SvelteKit 5 (runes) + Vite + TypeScript + Tailwind CSS 4 | `3031` | Вітрина клієнта: каталог, кошик, оформлення, замовлення, трекінг, чат |

## Маршрути

Маршрутизація файлова, у `src/routes/`:

| Маршрут | Екран |
|---------|-------|
| `/` | Головна сторінка |
| `/catalog` | Каталог товарів із пагінацією |
| `/category/[slug]` | Товари однієї категорії |
| `/product/[slug]` | Деталі товару (завантажуються у `+page.ts` через `getProduct`) |
| `/cart` | Вміст кошика |
| `/checkout` | Оформлення й оплата карткою через Stripe |
| `/login`, `/register` | Вхід / реєстрація |
| `/orders` | Замовлення клієнта (`GET /orders/my`) |
| `/orders/[id]` | Трекінг замовлення: кроки статусу, карта й чат |
| `/profile/[slug]` | Профіль клієнта (`getCurrentUser` / `updateCurrentUser`) |
| `/demo`, `/demo/playwright` | Демо- та тестові сторінки |

## Керування станом

- **Runes Svelte 5** у компонентах: `$props()`, `$state()`, `$derived()`, `$effect()`. Застарілий `export let` не працює, бо runes примусово увімкнено в `svelte.config.js`.
- **Store-модулі** в `src/lib/stores/`:
  - `userStore.ts` — поточний користувач, дублюється в `localStorage.user`.
  - `cartStore.ts` — позиції кошика в пам'яті (`addItem`, `removeItem`, `clear`).
  - `cartCount.ts` — лічильник для бейджа, що рахується з `GET /cart` (`refreshCartCount`).
  - `toast.ts` — короткочасні сповіщення про успіх/помилку (`showToast`).
  - `socketStore.ts` — тонка обгортка над `WebSocket` (`connect`, `send`, `onMessage`).

## Як застосунок говорить з API

`src/lib/api.ts` надає `apiFetch<T>()`:

- Базова адреса `API_URL = PUBLIC_API_URL || 'http://localhost:3000'` (`PUBLIC_API_URL` береться з `$env/static/public`).
- Додає заголовок `Authorization: Bearer <accessToken>` зі `localStorage`.
- На `401` (крім ендпоінтів `/auth/*`) робить один `POST /auth/refresh`, зберігає нову пару токенів і повторює запит; `refreshInFlight` дедуплікує паралельні оновлення.
- Завжди повертає `{ data, error, status }` і ніколи не кидає виняток.

Сторінка трекінгу (`/orders/[id]`) поєднує REST, WebSocket і полінг:

- Відкриває `ws(s)://<API_URL>/ws`, надсилає `auth`, а потім `subscribe` на `order:<id>`.
- Реагує на `order_updated` (перезавантаження трекінгу), `courier_location` (переносить мітку) і `chat_message` (перезавантаження повідомлень); після закриття перепідключається через `3 с`.
- Поллить `GET /orders/:id/tracking` і повідомлення замовлення кожні `5 с`, зупиняючись, коли замовлення переходить у `delivered`.
- Малює мітки кур'єра й адреси доставки та пряму лінію маршруту на карті Leaflet / OpenStreetMap.

До того ж: [Realtime](/uk/підключення_протокол), [Трекінг і чат](/uk/трекінг).

## Авторизація та ролі

- Токени зберігаються у `localStorage`: `accessToken`, `refreshToken`, `user`.
- У UI немає рольового захисту — це клієнтський застосунок. Авторизацію виконує бекенд (`allowRoles`). Деталі: [Життєвий цикл замовлення](/uk/статуси_переходи).

## Ключові реалізовані фічі

- Каталог із пагінацією та фільтром за категоріями.
- Сторінка товару з категоріями, тегами й інгредієнтами та кнопкою «Add to Cart».
- Кошик і оплата карткою через Stripe (`POST /payments/create-intent`, далі `POST /payments/confirm`; форма картки через `@stripe/stripe-js`).
- Список замовлень і живий трекінг із картою та чатом замовлення.
- Сповіщення-тости для зворотного зв'язку кошика й API.
