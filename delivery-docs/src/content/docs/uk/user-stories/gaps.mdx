# Пробіли й обмеження

## Що відрізняється від початкових специфікацій

| Було в `project.*.spec.md` | Зараз у коді |
|----------------------------|--------------|
| Owner panel на Angular | React 18 + Vite + TanStack Query + Recharts |
| Кур'єр лише змінює статуси | Плюс маршрут OSRM, геолокація, чат, призначення кур'єра на замовленні |
| Клієнт бачить лише список замовлень | Плюс сторінка трекінгу з картою, кур'єром і чатом |
| Чат клієнт ↔ адмін | Чат по замовленню: клієнт ↔ кур'єр ↔ адмін |
| Координати не зберігалися | `orders.lat/lng`, `courier_locations` |
| Статуси змінювались без правил | Матриця переходів + права ролей + захист від перехоплення замовлення |
| Немає фінансового модуля | `staff_salaries`, `payroll_payments`, `expenses`, `audit_logs`, чистий прибуток |

## Відомі прогалини

- Немає окремої адмін-панелі: роль `admin` входить у owner-панель, але UI-гард пускає лише `owner`.
- Немає WebRTC-дзвінка (див. нижче), лише `tel:`.
- Немає історії переміщень кур'єра (зберігається лише остання точка).
- Немає дії «оплачено готівкою» → такі замовлення не потрапляють у дохід.
- Немає UI відгуків.
- Немає транзакційного захисту від одночасного прийняття замовлення двома кур'єрами.
- Документ OpenAPI охоплює лише частину маршрутів; `/orders`, `/chats`, `/geo` й `/owner` там не описані.
- Старі `/chats` (клієнт ↔ адмін) залишені в API, але UI їх не використовує; робочий чат — лише `/chats/order/:orderId`.

## Про WebRTC (дзвінок через інтернет)

Технічно можливо, але WebSocket — не транспорт для дзвінка:

- **WebSocket** передає лише сигналізацію: `call_offer`, `call_answer`, `ice_candidate`, `call_hangup`. Інфраструктура вже є (`broadcastToUser`, канали, авторизація).
- **Медіа** йде окремо: WebRTC (SRTP/DTLS) напряму між клієнтом і кур'єром.
- Потрібні **STUN** (визначення публічної адреси) і **TURN** (ретрансляція за симетричним NAT). Публічний STUN безкоштовний; TURN — це сервер і трафік, тобто гроші.
- `getUserMedia` працює лише в **secure context**: `https://` або `localhost`. На `http://192.168.x.x` мікрофон недоступний.
- Потрібні UI-стани: виклик, дзвінок, відхилення, завершення, дозволи — плюс обробка мобільних обмежень (фон, блокування екрана, iOS Safari).

Тобто дзвінок — це окрема фіча: сигналізація через наявний WS + TURN-сервер + нові екрани в обох застосунках.
