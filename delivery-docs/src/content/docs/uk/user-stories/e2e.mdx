# Наскрізні сценарії

Сценарії, перевірені в межах кількох застосунків.

## E2E-1. Повний цикл доставки ✅

1. Клієнт оформлює замовлення (готівка) з адресою → `created`.
2. Кухня: `cooking` → `ready`.
3. Кур'єр приймає → `on_the_way`, `courierId` записаний.
4. Кур'єр надсилає локацію → клієнт бачить маркер.
5. Кур'єр: `delivered` → клієнт бачить завершений таймлайн.
6. Owner-панель: замовлення з кур'єром з'являється в `/kitchen`.

## E2E-2. Сесія протухла ✅

У `courier-app` підміна access-токена на невалідний дає `GET /orders` `401` → `POST /auth/refresh` `200` → повторний `GET /orders` `200`, список на місці. Якщо невалідні і access, і refresh — виконується `logout()` і застосунок переходить на `/`. `frontend`, `сhef-panel` й `ower-panel` поводяться так само (перехоплювачі, що роблять одну повторну спробу).

## E2E-3. Чат між клієнтом і кур'єром ✅

Клієнт (або адмін у клієнтському UI) пише → `201`, `sender` визначений роллю; кур'єр бачить повідомлення у своїй картці; власник отримує `chat_message` через WebSocket.
