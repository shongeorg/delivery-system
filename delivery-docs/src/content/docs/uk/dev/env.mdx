# Змінні середовища

Лише `backend` і `frontend` читають змінні середовища. `courier-app`, `сhef-panel` й `ower-panel` не мають файлу `.env` — їхні API-клієнти зашивають `http://localhost:3000`.

## Бекенд — `backend/.env`

Скопіюйте `backend/.env.example` у `backend/.env`.

```
# Stripe
STRIPE_SECRET_KEY=
STRIPE_PUBLISHABLE_KEY=
STRIPE_WEBHOOK_SECRET=

# Neon PostgreSQL
POSTGRES_URL=

# JWT
JWT_SECRET=
JWT_REFRESH_SECRET=
JWT_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=7d

# Завантаження файлів
MAX_FILE_SIZE=5242880
UPLOAD_PATH=./uploads

# Сервіси зображень (для сідингу)
UNSPLASH_API_KEY=
PEXELS_API_KEY=
PIXABAY_API_KEY=

# Сервер
PORT=3000
NODE_ENV=development
```

Ключові моменти:

- `POSTGRES_URL` — рядок підключення Neon; його також читає `backend/drizzle.config.ts` для `db:push` / `db:generate`.
- `JWT_SECRET` і `JWT_REFRESH_SECRET` читаються на етапі завантаження модуля в `backend/src/utils/auth.ts`, тому `.env` мусить бути завантажений до старту, а порядок імпортів має значення.
- `STRIPE_PUBLISHABLE_KEY` — це бекенд-копія; фронтенд користується власним `PUBLIC_STRIPE_PUBLISHABLE_KEY`.
- `UNSPLASH_API_KEY` / `PEXELS_API_KEY` / `PIXABAY_API_KEY` використовує лише скрипт сідингу для демо-зображень.

## Фронтенд — `frontend/.env`

Скопіюйте `frontend/.env.example` у `frontend/.env`.

```
PUBLIC_API_URL=http://localhost:3000
PUBLIC_WS_URL=ws://localhost:3000/ws

# Stripe (скопіюйте з кореневого .env.base)
PUBLIC_STRIPE_PUBLISHABLE_KEY=
```

Змінні читаються через `$env/static/public` у `src/lib/api.ts`, тому в браузер потрапляють лише імена з префіксом `PUBLIC_`.

## Застосунки без `.env`

| Застосунок | URL API |
|-------------|---------|
| `courier-app` | `http://localhost:3000` (`src/api/client.js`) |
| `сhef-panel` | `http://localhost:3000` (`src/api/axios.ts`) |
| `ower-panel` | `http://localhost:3000` |

Вони зашиті в код; `/api`-проксі Vite для кухні налаштований, але її API-клієнт його не використовує.
