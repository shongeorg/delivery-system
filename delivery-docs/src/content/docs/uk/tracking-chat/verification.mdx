# Результати перевірки

Ці перевірки виконано наживо проти запущеного бекенда та БД із сід-даними.

| Область | Що перевіряли | Результат |
|---------|----------------|-----------|
| REST | Кур'єр приймає замовлення → `courierId` заповнений | OK |
| REST | Другий кур'єр намагається прийняти те саме замовлення → `409` | OK |
| REST | `PUT /orders/:id/location` | `200` |
| REST | `GET /orders/:id/tracking` віддає точку клієнта й кур'єра | OK |
| REST | `POST` чату повертає `201`, а історія — повідомлення | OK |
| WebSocket | Owner підписався на `order:<id>`; кур'єр надіслав локацію → owner отримав `courier_location` | OK |
| WebSocket | Повідомлення в чат → отримано `chat_message` | OK |
| Браузер | Checkout з «Use my location» | у тестовому Chrome геолокація `denied`, тому спрацював геокодинг адреси |
| Браузер | Сторінка трекінгу | показала таймлайн, карту, «Courier position updated» і картку кур'єра |
| Браузер | Повідомлення в чаті | з'явилося і в клієнта, і в кур'єра |
| Браузер | Owner-панель на кухні | показала «Courier: Curier 1» |
| OSRM | Перевірка доступності | `code: Ok`, 27.7 км / 38 хв для тестової пари точок |

## Що не перевірено

- **Маршрут у браузері не перевірений**, бо без геолокації немає стартової точки, тож маршрут не будується.
