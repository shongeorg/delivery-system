# Чат замовлення

На кожне замовлення припадає один чат (`chats.orderId` унікальний). Учасники визначаються із самого замовлення; окремої таблиці членства немає.

## Учасники

| Хто | Як визначається | `sender` у повідомленні |
|-----|-----------------|-------------------------|
| Клієнт | `order.userId === userId` | `user` |
| Кур'єр | `order.courierId === userId` і роль `courier` | `courier` |
| Адмін / власник | роль `owner` або `admin` | `admin` |

## Права

- Читати й писати може лише учасник замовлення: власник, призначений кур'єр або `owner`/`admin`.
- Чужий кур'єр отримує `403`, навіть якщо бачить замовлення у списку.
- Чат створюється ліниво при першому зверненні (`GET /chats/order/:orderId`), де `userId` виставляється рівним власнику замовлення.

## Ендпоінти

Вони визначені в `backend/src/routes/chats.ts`.

| Метод | Шлях | Опис |
|-------|------|------|
| `GET` | `/chats/order/:orderId` | Отримати або створити чат |
| `GET` | `/chats/order/:orderId/messages` | Історія (за зростанням часу) |
| `POST` | `/chats/order/:orderId/messages` | `{ "text": "..." }` → `201` |

На `POST` функція `resolveSender` визначає `sender` у такому порядку: призначений кур'єр (`courier`), роль персоналу (`admin`), власник замовлення (`user`); у всіх інших випадках — `403`.

## Доставка

Нове повідомлення одразу розсилається в канал `order:<id>` як `chat_message`, тому інші учасники бачать його без перезавантаження, за умови відкритого сокета:

```mermaid
sequenceDiagram
  participant S as Відправник
  participant API as Бекенд
  participant WS as канал order:&lt;id&gt;

  S->>API: POST /chats/order/:orderId/messages { text }
  API->>API: resolveSender (courier / admin / user)
  API->>WS: chat_message
  API-->>S: 201 message
  Note over WS: інші учасники перезавантажують історію на chat_message
```

Оскільки події не ставляться в чергу, клієнт під час перепідключення пропустить подію й покладається на полінг повідомлень кожні 5 с. Далі — [UI чату](/uk/tracking-chat/chat-ui) та [Потік даних](/uk/tracking-chat/data-flow).

## Старий API чату

Старий API `/chats` (клієнт ↔ адмін, без замовлення) залишився для сумісності, але жоден UI його не використовує.
